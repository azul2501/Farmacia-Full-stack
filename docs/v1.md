# Botica Farma V1

Fecha: 22 de octubre de 2026. Rama: `v1-recorte`.

La V1 es un punto de venta para una **botica de una sola tienda que vende en mostrador**: vende, controla su stock por lote y vencimiento, y cierra su caja. La botica se registra sola desde la web y prueba el sistema 30 días gratis. Tú administras todas las boticas desde el panel de superadmin.

Este documento describe qué hace cada módulo, qué API usa y para qué. El plan completo de fases está en el documento "Plan de recorte – Botica Farma MVP".

## 1. Cómo funcionan las versiones

Cada módulo pertenece a una versión. La versión publicada se define con una variable y debe ser la misma en backend y frontend:

| Dónde | Variable | Valor V1 |
| --- | --- | --- |
| Backend (Django) | `APP_VERSION` | `1` |
| Frontend (Next.js) | `NEXT_PUBLIC_APP_VERSION` | `1` |
| Docker (`compose.yml`) | `APP_VERSION` en `.env` | `1` (se pasa a los dos) |

- **Frontend:** `frontend/lib/modules.ts` es la única lista de rutas con su versión. El menú (`components/sidebar.tsx`) muestra solo lo habilitado y cualquier ruta de una versión posterior, o que no esté en la lista, responde 404 aunque se escriba la URL. `frontend/lib/features.ts` tiene las funciones opcionales (crédito, finanzas, varias sucursales).
- **Backend:** `FEATURE_VERSIONS` en `config/settings/base.py` y el helper `apps/core/features.py`. Los endpoints de versiones posteriores responden 404 y las reglas de negocio se aplican en los servicios.

| Función | Versión | Qué pasa en la V1 |
| --- | --- | --- |
| `credit_sales` | 2 | El POS solo vende al contado; la API rechaza ventas a crédito. |
| `finance` | 2 | Cuentas por cobrar y pagar, gastos e ingresos: 404. Las compras solo al contado. |
| `multi_branch` | 3 | Solo roles Dueño y Cajero; la tienda se asigna sola. |
| `transfers` | 3 | Transferencias: 404. |
| `customer_requests` | 3 | Solicitudes programadas: 404. |

El código de V2 y V3 sigue en el repositorio; para habilitarlo basta con subir la versión.

## 2. Módulos de la V1

Todas las rutas de la API empiezan con `/api/v1/`. Salvo el registro y el login, todas piden sesión (JWT) y el encabezado `X-Company-ID` lo maneja el frontend automáticamente.

### Registro de botica (`/signup`)

La botica crea su cuenta sola, sin hablar contigo.

- Pide: nombre de la botica, RUC, dirección, nombre del dueño, celular, correo y contraseña.
- Valida el RUC: formato y dígito verificador de SUNAT, que no esté registrado, y que figure **ACTIVO y HABIDO** en SUNAT con el servicio gratuito de consulta. Si el servicio no responde, el registro sigue y la botica queda "RUC por verificar" en el panel.
- Crea en una sola operación: empresa, sucursal "Principal", almacén "Tienda", terminal "Mostrador", "Caja 1", el usuario dueño y su membresía. La prueba dura los días que diga el plan por defecto (30).
- Máximo 5 registros por hora por IP. No se envía ningún correo.

| API | Para qué |
| --- | --- |
| `POST /signup/` | Crear la botica y su dueño. Público. |
| `POST /auth/login/` | Iniciar sesión justo después del registro. |

### Inicio (`/`)

Resumen del día y los primeros pasos de una cuenta nueva.

- Ventas del día, cajas abiertas, productos en stock mínimo, lotes por vencer y vencidos, diferencias de caja y ventas por medio de pago.
- **Primeros pasos** (solo hasta completarlos): cargar productos, registrar stock y abrir la caja.
- Aviso arriba de la pantalla con los días de prueba que quedan, o con el bloqueo si la prueba terminó.
- **Alertas DIGEMID:** las últimas 5 alertas sanitarias. Si una menciona un lote que la botica tiene en stock (y el registro sanitario coincide, cuando la alerta lo trae), se marca en rojo con el producto y el lote, para separarlo y no venderlo.

| API | Para qué |
| --- | --- |
| `GET /reports/dashboard/` | Cifras del día y alertas de stock y vencimientos. |
| `GET /digemid/alerts/?limit=5` | Alertas DIGEMID, cada una con los lotes de la botica que coinciden. |
| `GET /products/`, `GET /stock/`, `GET /cash-sessions/` | Saber qué primeros pasos ya se hicieron (solo se pide el total). |
| `GET /auth/context/` | Datos de la botica, incluido el estado de la suscripción. |

### Punto de venta (`/pos`)

Venta en mostrador al contado.

- Busca o escanea el producto, saca el stock por lote con FEFO (vence primero, sale primero) y no vende lotes vencidos.
- Medios de pago: efectivo (con vuelto), Yape, Plin y tarjeta. Descuentos con motivo.
- Imprime la nota de venta (térmica 80 mm o A4).
- Si la prueba terminó o la cuenta está suspendida, la venta se rechaza.

| API | Para qué |
| --- | --- |
| `GET /products/` | Buscar productos por nombre. |
| `GET /product-variants/by-barcode/` | Encontrar la presentación al escanear el código de barras. |
| `GET /stock/` | Stock disponible por lote. |
| `GET /cash-sessions/` | Caja abierta del usuario. |
| `GET /pos-terminals/` | Terminal de la tienda (se crea sola en el registro). |
| `GET /customers/` | Cliente opcional en la nota de venta (DNI o nombre). |
| `POST /sales/checkout/` | Registrar la venta (idempotente: un doble clic no duplica). |
| `GET /sales/{id}/` | Datos para imprimir la nota. |

### Ventas (`/venta`)

Historial de ventas.

- Filtros, detalle, reimpresión y anulación (devuelve el stock y el dinero a la caja si sigue abierta).

| API | Para qué |
| --- | --- |
| `GET /sales/` | Listado de ventas. |
| `GET /sales/{id}/` | Detalle. |
| `POST /sales/{id}/cancel/` | Anular una venta. |

### Productos (`/producto`)

Catálogo de la botica.

- Crear y editar productos con presentaciones (caja, blíster, unidad), precios, código de barras y control de lote y vencimiento. Los datos farmacéuticos (principio activo, DIGEMID, etc.) van plegados en "Información farmacéutica y adicional".
- Importar y exportar por CSV con plantilla.
- **Agregar desde el catálogo:** busca en el catálogo maestro (nombre o principio activo, mínimo 3 letras) y agrega el producto con el precio sugerido ya puesto (se puede cambiar); opcionalmente costo, stock mínimo y código de barras. Los medicamentos se crean con control de lote y vencimiento; los insumos (alcohol, gasas, jeringas…) van a la categoría "Insumos y cuidado personal" sin lote. Los que ya están en la botica aparecen como "En tu catálogo". Se pueden **marcar varios** (o "Marcar todos los resultados") y agregarlos de una vez con "Agregar seleccionados", o con el buscador vacío usar **"Cargar toda la lista"** para traer toda la lista base con su precio sugerido; después el dueño ajusta precios y desactiva lo que no vende. En la carga masiva se saltan los que ya están y los que no tienen precio sugerido.

| API | Para qué |
| --- | --- |
| `POST /digemid/products/bulk-add/` | Agrega varios: `{"ids": [...]}` o toda la lista base `{"all_base": true}`, con el precio sugerido. Devuelve agregados, ya existentes, sin precio y errores. Dueño. |
| `GET /digemid/products/base-summary/` | Total de la lista base y cuántos ya tiene la botica. |
| `GET /digemid/products/?search=` | Buscar en el catálogo maestro (20 por página); trae `suggested_price`, `product_type` y `source`. |
| `POST /digemid/products/{id}/add/` | Agregar ese producto a la botica con su precio. |
| `GET /digemid/products/by-barcode/?code=` | Encontrar en el catálogo un código de barras que otra botica ya enlazó. |
| `GET/POST /products/`, `GET/PATCH /products/{id}/` | Listar, crear y editar productos. |
| `DELETE /products/{id}/` | Desactivar (no se borra). |
| `GET /products/by-barcode/` | Buscar por código al escanear. |
| `GET /products/template/`, `POST /products/import-preview/`, `POST /products/import-commit/` | Importar productos por CSV: plantilla, revisión previa y carga. |
| `GET /products/export/` | Exportar el catálogo. |
| `GET/POST /categories/`, `/laboratories/`, `/active-ingredients/`, `/therapeutic-actions/` | Listas que se eligen o se crean desde el formulario del producto. |
| `/product-variants/`, `/product-barcodes/`, `/product-locations/` | Presentaciones, códigos de barras y ubicación en estante. |

### Proveedores (`/proveedor`)

Distribuidoras a las que la botica compra.

| API | Para qué |
| --- | --- |
| `GET/POST /suppliers/`, `PATCH/DELETE /suppliers/{id}/` | Listar, crear, editar y desactivar proveedores. |

### Ingreso de mercadería (`/compra`)

Registrar la mercadería que llega del proveedor.

- Se guarda en borrador; al confirmar, crea los lotes con su vencimiento y suma el stock. Solo al contado en la V1.
- Si la prueba terminó o la cuenta está suspendida, no se puede confirmar.

| API | Para qué |
| --- | --- |
| `GET/POST /purchases/`, `PATCH /purchases/{id}/` | Listar, crear y editar borradores. |
| `POST /purchases/{id}/receive/` | Confirmar la recepción: lotes, stock e historial. |
| `POST /purchases/{id}/cancel/` | Anular un borrador. |

### Stock y vencimientos (`/inventario`)

Existencias por lote.

- Stock por lote con su vencimiento, ajustes con motivo (merma, conteo, vencido) y carga del stock inicial por CSV con validación previa.

| API | Para qué |
| --- | --- |
| `GET /stock/` | Stock por lote con su vencimiento. |
| `POST /stock/adjustments/` | Ajustar una cantidad con su motivo. |
| `GET /products/stock-template/`, `POST /products/stock-import/` | Plantilla y carga del stock inicial. |

### Historial del producto (`/consulta/kardex`)

Antes "Kardex": todas las entradas y salidas de cada producto con su saldo.

| API | Para qué |
| --- | --- |
| `GET /inventory-movements/` | Movimientos filtrados por fecha y producto. |

### Caja (`/caja`)

- Apertura con monto inicial, arqueos parciales y cierre con el efectivo contado y la diferencia.

| API | Para qué |
| --- | --- |
| `GET /cash-registers/` | Cajas de la botica. |
| `POST /cash-registers/open/` | Abrir caja. |
| `GET /cash-sessions/` | Sesiones de caja. |
| `GET/POST /cash-sessions/{id}/counts/` | Arqueos. |
| `POST /cash-sessions/{id}/close/` | Cerrar la caja. |

### Usuarios (`/usuario`)

- El dueño crea cajeros (o más dueños). En la V1 solo existen los roles **Dueño** y **Cajero**; la tienda se asigna sola. Desactivar en lugar de borrar y restablecer contraseñas.

| API | Para qué |
| --- | --- |
| `GET/POST /users/`, `PATCH /users/{id}/` | Listar, crear y editar usuarios. |
| `POST /users/{id}/reset-password/` | Restablecer la contraseña (no hay correos en la V1). |
| `POST /auth/password/change/` | Cambiar la propia contraseña. |

### Sesión (todas las pantallas)

| API | Para qué |
| --- | --- |
| `POST /auth/login/` | Iniciar sesión; guarda el refresh token en una cookie HttpOnly. |
| `POST /auth/refresh/` | Renovar el acceso sin volver a escribir la contraseña. |
| `POST /auth/logout/` | Cerrar sesión. |
| `GET /auth/context/` | Usuario, botica, rol, permisos y sucursales. |
| `GET /warehouses/` | Almacén de la tienda (se crea solo en el registro). |
| `GET /health/` | Verificación de que el servidor responde (Docker). |

La documentación interactiva de todas las APIs está en `http://localhost:8000/api/docs/`.

## 3. Suscripción y planes

| Estado | Significado | Puede vender |
| --- | --- | --- |
| En prueba | Recién registrada; dura los días del plan. | Sí, hasta que vence la prueba. |
| Activa | Pagó su plan. | Sí. |
| Suspendida | La suspendiste desde el panel. | No. |

Con la prueba vencida o la cuenta suspendida, la botica **puede entrar y ver sus datos, pero no puede vender ni confirmar ingresos de mercadería**. El precio y los días de prueba se editan en el panel, en Planes; al migrar se crea el "Plan Básico" con precio 0 y 30 días para que lo ajustes.

## 4. Panel de superadmin (`http://localhost:8000/admin/`)

Hecho con Django Unfold. Solo entran cuentas `is_superuser` (`python manage.py createsuperuser`).

| Pantalla | Para qué |
| --- | --- |
| Inicio | Boticas registradas, en prueba, con prueba vencida, pagando, suspendidas y con RUC por verificar; ventas de las últimas 24 horas; últimos registros; boticas sin ventas en 7 días. |
| Boticas | Listado con estado, plan, fin de prueba, RUC verificado y última venta. Acciones: **Activar plan**, **Extender la prueba 15 días**, **Suspender**. **Agregar** una botica crea todo para vender (tienda, almacén, terminal, caja y dueño) y muestra una contraseña temporal para el dueño. |
| Planes | Precio mensual, días de prueba y cuál es el plan por defecto. |
| Usuarios | Buscar por correo o celular, ver sus boticas, cambiar contraseñas. |
| Ventas y Productos | Solo lectura, para dar soporte. |
| Auditoría | Registro de acciones, incluido cada registro de botica. |
| DIGEMID | Catálogo maestro (se agrega y se corrige el precio sugerido; no se borra), alertas sanitarias (se pueden corregir o agregar a mano) y códigos de barras compartidos. |

## 5. Datos de DIGEMID

DIGEMID no tiene una API pública, así que el sistema guarda una copia propia de sus datos públicos.

**Lista base (ya incluida).** El catálogo maestro arranca con 565 productos de `backend/apps/digemid/data/catalogo_base.csv`:

- 434 genéricos esenciales del anexo de la RM 220-2024-MINSA (código `RM220-001`…`RM220-434`), con principio activo, concentración y forma farmacéutica.
- 131 productos comerciales e insumos comunes (código `BASE-001`…), como Panadol, Apronax, alcohol, gasas y jeringas.
- Precio sugerido por unidad en 457 de ellos. Es **referencial**: está estimado a partir de precios típicos de botica en Perú y cada botica lo cambia. Los de uso hospitalario, oncológico o controlado no traen precio.

Se carga sola al levantar el `api` (`load_base_catalog --if-empty`, solo si aún no está). Para recargarla después de cambiar el CSV: `docker compose exec api python manage.py load_base_catalog` (pisa los precios sugeridos cambiados en el panel). Los productos de la lista base no traen registro sanitario ni laboratorio; la botica los completa en la ficha si quiere.

**Catálogo de DIGEMID.** Se carga desde el Excel del Catálogo de Productos Farmacéuticos de DIGEMID (pedido a catalogacion@minsa.gob.pe). Convive con la lista base: usa los códigos de DIGEMID y no toca precios sugeridos. Para cargarlo o actualizarlo (una vez al mes):

```bash
docker compose cp catalogo_digemid.xlsx api:/tmp/catalogo.xlsx
docker compose exec api python manage.py import_digemid_catalog /tmp/catalogo.xlsx --dry-run   # revisar columnas
docker compose exec api python manage.py import_digemid_catalog /tmp/catalogo.xlsx
```

Las columnas se reconocen por nombre (Cod_Prod, Nom_Prod, Concent, Nom_Form_Farm, Presentac, Num_RegSan, Nom_Titular, Nom_Fabricante, Nom_IFA, Situacion y variantes). Acepta .xlsx y .csv. Volver a cargarlo actualiza los productos existentes por su código DIGEMID.

**Códigos de barras compartidos.** DIGEMID no publica códigos de barras. Cuando una botica agrega un producto del catálogo con su código de barras, ese enlace queda guardado para todas.

**Alertas sanitarias.** DIGEMID publica cada alerta como PDF (`/Archivos/Alertas/{año}/ALERTA_{número}-{aa}.pdf`). El comando `sync_digemid_alerts` busca las nuevas, lee el PDF y extrae registros sanitarios y lotes. Corre una vez al día con el servicio `digemid-sync` (en local: `docker compose --profile jobs up -d`; en producción siempre). A mano: `docker compose exec api python manage.py sync_digemid_alerts`. La extracción de lotes es automática y puede fallar en PDFs con formato distinto; desde el panel se corrige o se agrega una alerta.
